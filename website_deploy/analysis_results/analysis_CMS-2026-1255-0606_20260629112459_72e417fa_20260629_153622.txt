# Comment Analysis: CMS-2026-1255-0606_20260629112459_72e417fa

## 1. COMMENTER INFORMATION

- **Author/Organization name:** Epic Systems Corporation; signed by Jim McDermott, R&D
- **Stakeholder type:** Technology Vendor
- **Credentials or expertise mentioned:** Epic develops e-prescribing, medication management, electronic prior authorization, clinical workflow, and health plan administration software used by providers and payers.

## 2. EXECUTIVE SUMMARY

Epic supports NCPDP standards for pharmacy-benefit drug prior authorization and supports expanding the FHIR Prior Authorization API to medical-benefit drugs, but asks CMS to adjust timelines and remove or defer requirements that are not workflow-appropriate or mature. It recommends removing NCPDP PANotification from payer requirements, extending pharmacy-benefit compliance to at least 24 months after the final rule, requiring CRD/PAS v2.2.1 by January 1, 2028, recommending rather than requiring DTR for now, and using January 1, 2029 if all three IGs are mandated. Epic also supports endpoint reporting, public PA metrics, CDex for HIPAA attachments, and several RFI concepts while opposing payer API certification.

## 4. DETAILED POSITIONS

**Topic 1: NCPDP standards for pharmacy benefit drugs**
- **Provision ID:** PA-DRUG-PHARMACY
- **Position:** Support/Modify
- **Rationale:** SCRIPT, F&B, and RTPB are complementary, purpose-built standards already used in prescribing workflows and Part D. PANotification is not a payer transaction.
- **Specific request:** Finalize NCPDP standards; treat F&B and RTPB as complementary; rely on NCPDP RTPB rather than introducing a parallel HL7 RTPBC workflow; remove PANotification from payer-required SCRIPT transactions.

**Topic 2: Pharmacy-benefit compliance timeline**
- **Provision ID:** IMPLEMENTATION-TIMELINE
- **Position:** Modify
- **Rationale:** Newly impacted payers need to build integrations, trading partner onboarding, testing protocols, and staff training in a fragmented ecosystem.
- **Specific request:** Set pharmacy-benefit drug PA compliance no earlier than 24 months after the final rule effective date.

**Topic 3: FHIR Prior Authorization API for medical benefit drugs**
- **Provision ID:** PA-DRUG-MEDICAL; FHIR-IG-REQUIRED
- **Position:** Support/Modify
- **Rationale:** FHIR expansion is the right direction, but version migration across payers and EHRs can disrupt existing CMS-0057-F integrations if timelines are not coordinated.
- **Specific request:** Require CRD v2.2.1 and PAS v2.2.1 by January 1, 2028; recommend rather than require DTR now due to CQL and implementation complexity. If all three IGs are required, set compliance at least 18 months after the final rule and no earlier than January 1, 2029.

**Topic 4: HIPAA administrative simplification scope**
- **Provision ID:** HIPAA-PA-STANDARDS
- **Position:** Clarify
- **Rationale:** Referral certification and authorization includes broader workflows, and CRD is not a replacement for broad X12 270/271 eligibility transactions.
- **Specific request:** Confirm FHIR standards apply only to prior authorization as defined at 45 CFR 162.103 and only replace the narrow 270/271 use for determining whether PA is required; use separate rulemaking for broader referral certification use cases.

**Topic 5: API endpoint registry**
- **Provision ID:** API-ENDPOINT-REPORTING
- **Position:** Support/Modify
- **Rationale:** Centralized endpoint discovery is useful, but payer-maintained manifests can reduce manual updates.
- **Specific request:** Use Bulk Publish for payer-to-CMS submission and CMS publication; require Incremental Updates; require notice only when manifest URLs change; use SMART User Access Brands for Patient Access endpoints and NDH Endpoint Profile with access control, environment type, and use-case extensions for other endpoints.

**Topic 6: Prior authorization metrics**
- **Provision ID:** API-USAGE-METRICS; TRANSPARENCY
- **Position:** Support/Clarify
- **Rationale:** Public metrics are valuable, but definitions and effective dates must support comparability and feasibility.
- **Specific request:** Define expedited requests clearly and give payers at least one full reporting period of advance notice before new non-drug metrics take effect.

**Topic 7: Additional IGs and standards maturity**
- **Provision ID:** ONC-STANDARDS-UPDATE; FHIR-IG-REQUIRED
- **Position:** Mixed
- **Rationale:** Some IGs are useful but not all are mature or appropriate for requirements.
- **Specific request:** Recommend ATR but do not require it yet; do not recommend or require Tiered OAuth; do not finalize CARIN Blue Button v2.2.0 or PDex Plan Net until issues are resolved; support CDex v2.1.0 as the HIPAA attachment standard.

**Topic 8: RFIs**
- **Provision ID:** GENERAL
- **Position:** Mixed
- **Rationale:** Epic offers practical implementation alternatives on event notifications, resiliency, certification, and step therapy.
- **Specific request:** Use existing event notification mechanisms and TEFCA rather than mandating new FHIR notifications; provide bridge payments and claims redundancy during cyber disruptions; oppose payer API certification in favor of testing tools and CMS implementation; explore Payer-to-Payer API support for step therapy.

## 5. SOLICITATION RESPONSES

- **S1/S2/S3/S18:** Supports requiring CRD/PAS v2.2.1, but recommends DTR rather than requiring it due to CQL complexity and version-transition risk.
- **S12:** Supports expanding the Prior Authorization API to medical-benefit drugs.
- **S14:** Supports NCPDP SCRIPT, F&B, and RTPB for pharmacy-benefit drugs.
- **S21/S22:** Requests timeline changes: 24 months after final rule for pharmacy-benefit NCPDP ePA; January 1, 2028 for CRD/PAS; January 1, 2029 if DTR is required.
- **S23/S24/S26/S27/S33:** Supports endpoint reporting with Bulk Publish, Incremental Updates, SMART User Access Brands, NDH Endpoint Profile extensions, and manifest-based updates.
- **S29/S34/S35:** Supports public PA metrics, requests a definition of expedited requests, and asks for at least one full reporting period of advance notice.
- **S44-S56:** Asks CMS to limit HIPAA FHIR standards to PA and not replace broad eligibility or referral certification functions without separate rulemaking.
- **S60-S65:** Comments on IG readiness: support CDex v2.1.0, recommend ATR only, exclude Tiered OAuth, delay CARIN Blue Button and PDex Plan Net requirements.
- **S66-S82:** Responds to RFIs on event notifications, resiliency, payer API certification, and step therapy.
