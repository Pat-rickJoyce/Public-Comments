---

## 2. EXECUTIVE SUMMARY

Firely strongly supports the proposed rule's expansion of ePA to drugs, mandatory FHIR IGs, HIPAA transaction modernization, and the RFI process, endorsing the Da Vinci Project's technical recommendations. The comment focuses entirely on three RFI areas: (1) electronic event notifications, recommending transition to HL7 FHIR Subscriptions R5 Backport with standardized payloads and FHIR-based provider directories; (2) healthcare resiliency/security, recommending UDAP via FAST Security IG and federated identity assurance frameworks; and (3) payer API implementation, recommending longitudinal synthetic datasets for end-to-end testing and a more rigorous, real-world-aligned payer API certification regime.

## 4. DETAILED POSITIONS

**Topic 1: Electronic Event Notifications — Mandate FHIR Subscriptions R5 Backport**
- **Provision ID:** GENERAL (RFI — event notifications)
- **Position:** Support / Recommend
- **Rationale:** Current hospital ADT notifications rely on legacy HL7 v2 interfaces that are verbose, unstructured, and lack deep clinical context. FHIR Subscriptions R5 Backport + Da Vinci Unsolicited Notifications IG provides targeted, scalable, actionable notifications, reusing structured EHR data without manual clinician input.
- **Specific request:** Mandate FHIR Subscriptions R5 Backport with standardized profiled FHIR Bundle payloads; collaborate with HL7 to establish clear notification triggering criteria; standardize provider directories using FHIR-based model for reliable endpoint routing.

**Topic 2: Da Vinci ATR List IG for Event Notifications**
- **Provision ID:** GENERAL (RFI — event notifications)
- **Position:** Support
- **Rationale:** ATR lists establish patient attribution relationships and enable dynamic adjustment of notification eligibility; network participation status should not be the primary determinant.
- **Specific request:** Work with HL7 to define standardized notification triggers (e.g., patient added to ATR list triggers proactive outreach); incorporate robust member-matching from advanced PDex IG versions.

**Topic 3: ONC Certification for Event Notification Subscriptions**
- **Provision ID:** FHIR-IG-REQUIRED, ONC-STANDARDS-UPDATE
- **Position:** Recommend
- **Rationale:** Conformance testing via Inferno would ensure vendor systems natively and securely support subscription-based notification workflows.
- **Specific request:** CMS should partner with ASTP/ONC to develop FHIR-based IGs for event notification subscriptions; validate via Inferno; align with ONC certification criteria.

**Topic 4: Healthcare Resiliency — Security Through UDAP and Federated Identity**
- **Provision ID:** GENERAL (RFI — resiliency)
- **Position:** Recommend
- **Rationale:** Security and interoperability are complementary. Fragmented credentialing undermines API security at scale; UDAP via FAST Security IG provides standardized digital certificate-based dynamic client registration and mutual authentication.
- **Specific request:** Require payers and providers to participate in at least one UDAP-leveraging network; require NIST IAL3-compliant identity assurance and modern SSO protocols.

**Topic 5: Payer API Testing — Longitudinal Synthetic Dataset**
- **Provision ID:** API-ENDPOINT-REPORTING, FHIR-IG-REQUIRED
- **Position:** Recommend
- **Rationale:** Inferno and Touchstone validate basic syntax but are insufficient for complex multi-IG real-world workflows. Payers/developers need realistic sandbox environments for full-loop CRD/DTR/PAS workflow testing before production rollout.
- **Specific request:** CMS should fund and provide a comprehensive, longitudinal synthetic dataset for end-to-end payer API testing with high-fidelity synthetic patient records.

**Topic 6: Payer API Certification — Robust Real-World Testing Model**
- **Provision ID:** API-ENDPOINT-REPORTING, FHIR-IG-REQUIRED
- **Position:** Support with modification
- **Rationale:** Early ONC 170.315(g)(10) certification showed systems passed siloed lab tests but failed in production; Real-World Testing frameworks proved unhelpful.
- **Specific request:** Shift payer API certification to edge-case, high-volume, realistic testing models; pair with transparent real-time noncompliance reporting; provide explicit guidance on internally developed payer systems and Information Blocking enforcement intersection.

**Topic 7: General Support for Rule Proposals**
- **Provision ID:** PA-DRUG-MEDICAL, FHIR-IG-REQUIRED, HIPAA-PA-STANDARDS
- **Position:** Support
- **Rationale:** Proposals to expand ePA to drugs, mandate mature FHIR IGs, and modernize HIPAA transactions build logically on prior interoperability rules and will reduce administrative burden while improving timely access to care.
- **Specific request:** Finalize these proposals; Firely endorses Da Vinci Project's technical recommendations.

- **S9 (Subscriptions backport):** Strongly supports HL7 FHIR Subscriptions R5 Backport as the foundation for modern patient event notifications; recommends standardized FHIR Bundle payloads.
- **S44 (FHIR appropriate for HIPAA PA):** Firely strongly supports replacing legacy HIPAA PA transaction standards with FHIR-based standards; endorses the HIPAA-PA-STANDARDS proposal direction.
- **S54 (Testing/certification for payer APIs):** Recommends edge-case, high-volume testing models for payer API certification; advocates CMS-funded longitudinal synthetic datasets; requires transparent noncompliance reporting.

- **S62 (Testing criteria):** ONC Inferno should validate conformance for event notification subscriptions; testing must simulate realistic multi-IG workflows beyond syntax validation.
- **General RFI — Event Notifications:** FHIR Subscriptions R5 Backport + Da Vinci Unsolicited Notifications IG; FHIR-based provider directories; ATR List IG for attribution-based eligibility; standardized triggering criteria with HL7.
- **General RFI — Resiliency:** UDAP via FAST Security IG; NIST IAL3-compliant identity assurance; SSO protocols; require payer/provider participation in UDAP network.
- **General RFI — Payer API Implementation:** CMS-funded longitudinal synthetic dataset; edge-case payer API certification; transparent noncompliance reporting; clarify internally developed payer system boundaries.

---

## 6. RECOMMENDATIONS

1. Mandate HL7 FHIR Subscriptions R5 Backport with standardized profiled FHIR Bundle payloads for patient event notifications.
2. Standardize provider directories using FHIR-based model (Practitioner, PractitionerRole, Organization, Endpoint) for automated, reliable notification routing.
3. Collaborate with HL7 to define standardized notification triggers and business rules.
4. Incorporate Da Vinci ATR List IG for attribution-based notification eligibility with dynamic adjustment; expand patient/member-matching capabilities via advanced PDex IG.
5. Partner with ASTP/ONC to develop FHIR-based event notification subscription IGs with Inferno-validated conformance aligned to ONC certification criteria.
6. Require payers and providers to participate in at least one UDAP-leveraging network; transition to NIST IAL3-compliant federated identity assurance and SSO.
7. Fund and provide a comprehensive, longitudinal synthetic dataset for end-to-end payer API testing of multi-IG workflows (CRD, DTR, PAS).
8. Shift payer API certification to edge-case, high-volume, realistic testing; add transparent real-time noncompliance reporting.
9. Provide explicit guidance on whether internally developed payer systems are subject to identical payer API certification requirements and how this intersects with Information Blocking enforcement.

---

## 7. CONCERNS & OBJECTIONS

- **Primary concerns:** Legacy HL7 v2 ADT entrenchment creates migration barriers to FHIR-based event notifications; lack of financial incentives for institutions to replace functional legacy interfaces; early ONC 170.315(g)(10) certification paradigm proved insufficient for real-world deployments; basic conformance testing tools inadequate for complex multi-IG payer workflows.
- **Potential negative impacts cited:** Siloed certification environments lead to systems that pass testing but fail in production; fragmented credentialing undermines API security; lack of end-to-end testing creates implementation risk for CRD/DTR/PAS workflows.
- **Implementation barriers mentioned:** Technical, financial, and operational resources required to migrate from HL7 v2 ADT to FHIR-based APIs; absence of realistic sandbox environments with high-fidelity synthetic data; lack of standards guidance for custom internally developed payer systems.

---

## 9. IMPACT ASSESSMENT

- **Affected stakeholders:** Payers, providers, health IT vendors, ACOs, value-based care organizations, state health programs, HL7/standards community.
- **Economic implications:** CMS funding of longitudinal synthetic datasets would reduce payer/vendor implementation costs; UDAP-based security reduces fragmented credentialing costs; edge-case certification may increase short-term burden but reduces production failure costs.
- **Technical feasibility:** FHIR Subscriptions R5 Backport, Da Vinci Unsolicited Notifications IG, and UDAP/FAST Security IG are mature and available; primary barriers are legacy v2 entrenchment and lack of comprehensive test infrastructure, both addressable through mandate and CMS investment.
- **Patient care impact:** Improved structured event notifications enable faster, more actionable care coordination for ACOs and value-based care models; better API security protects patient data in the expanding interoperability ecosystem.
