## 1. COMMENTER INFORMATION

- **Author/Organization name:** The Advocates for Responsible Care and the Rx in Reach Coalition.
- **Stakeholder type:** Advocacy Group / Professional Association
- **Credentials or expertise mentioned:** Represents a 52-member health-centered coalition; references provider organizations including the American Academy of Family Physicians, GASCO, and the American Society of Clinical Oncology.

## 2. EXECUTIVE SUMMARY

The commenter supports the goal of faster access to drugs but is concerned that the proposed rule's technical mandates will impose excessive cost, workflow disruption, and implementation delay. They request greater technical uniformity and rigorous real-world testing before implementation.

## 3. REGULATORY CONTEXT

- **Specific provisions addressed:** PA-DRUG-MEDICAL; PA-DRUG-PHARMACY; FHIR-IG-REQUIRED; GENERAL.
- **Regulatory citations mentioned:** Not addressed.
- **Standards referenced:** APIs, EHR systems, data exchange standards.

## 4. DETAILED POSITIONS

**Topic 1: Conflicting standards**
- **Provision ID:** PA-DRUG-MEDICAL / PA-DRUG-PHARMACY
- **Position:** Modify
- **Rationale:** Conflicting data exchange standards require costly cross-walking and may delay implementation.
- **Specific request:** Improve technical uniformity across standards.

**Topic 2: API and EHR implementation burden**
- **Provision ID:** FHIR-IG-REQUIRED
- **Position:** Modify
- **Rationale:** Building required APIs and updating EHRs would be expensive and logistically difficult.
- **Specific request:** Require rigorous real-world testing before implementation.

**Topic 3: Provider workflow impact**
- **Provision ID:** GENERAL
- **Position:** Oppose
- **Rationale:** Additional infrastructure mandates may burden clinical workflows without proven benefit.
- **Specific request:** Avoid mandates that add administrative and financial burden to provider practices and hospitals.

## 5. SOLICITATION RESPONSES

- **S12:** Identifies technical challenges with API construction, EHR updates, and cross-standard exchange.
- **S18:** Objects to mandatory technical requirements that may add burden without proven benefit.
- **S21:** Implies the proposed implementation timeline is risky because technical complexity may cause delays.
- **S22:** Raises cost concerns related to standards implementation and system updates.
- **S37:** Requests real-world testing before implementation due to expected implementation challenges.

## 6. RECOMMENDATIONS

1. Reduce conflicts among required data exchange standards.
2. Avoid costly cross-walking requirements where possible.
3. Conduct rigorous real-world testing before implementation.
4. Reconsider mandates that impose new infrastructure and workflow burdens without demonstrated benefit.

- **Primary concerns:** Conflicting standards, high cost, EHR update burden, and workflow disruption.
- **Potential negative impacts cited:** Implementation delays and delayed patient care.
- **Implementation barriers mentioned:** Cross-walking, API development, EHR upgrades, administrative complexity.
