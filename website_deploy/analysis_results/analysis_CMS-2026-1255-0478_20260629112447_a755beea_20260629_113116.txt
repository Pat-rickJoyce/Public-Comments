# Comment Analysis Template: CMS-2026-1255-0001

## 1. COMMENTER INFORMATION

- **Author/Organization name:** Blue Cross Blue Shield of Massachusetts (BCBSMA); signed by Jeremy W. Meisinger, Esq., Senior Director, Federal Affairs.
- **Stakeholder type:** Payer.
- **Credentials or expertise mentioned:** Not-for-profit Massachusetts health plan founded in 1937; member of the Blue Cross Blue Shield system; federal affairs and regulatory perspective.

## 2. EXECUTIVE SUMMARY

BCBSMA is generally supportive of extending the Prior Authorization API to drugs covered under the medical benefit, but asks CMS to tie compliance to final technical guidance and to address the lack of bidirectional provider-to-payer data exchange. It also requests a phased approach to public prior authorization metric reporting and recommends pausing additional API implementation requirements until CMS has reviewed meaningful usage metrics.

## 3. REGULATORY CONTEXT

- **Specific provisions addressed:** PA-DRUG-MEDICAL; API-USAGE-METRICS; TRANSPARENCY-related public prior authorization metric reporting; FHIR-IG-REQUIRED; GENERAL provider-to-payer interoperability.
- **Regulatory citations mentioned:** Social Security Act section 1857(e)(1); Proposed Rule citations 91 Fed. Reg. 19890, 19948.
- **Standards referenced:** FHIR; bulk FHIR; Certified Electronic Health Record technology; TEFCA; Prior Authorization API.

## 4. DETAILED POSITIONS

**Topic 1: Medical benefit drugs in the Prior Authorization API**
- **Provision ID:** PA-DRUG-MEDICAL
- **Position:** Modify
- **Rationale:** BCBSMA supports streamlining prior authorization for providers and members while preserving prior authorization as an affordability and utilization management tool. It argues that the uncertain final rule timeline and need for further technical guidance make the October 1, 2027 date potentially premature.
- **Specific request:** Set the compliance date as the later of 12 months after publication of final technical guidance or October 1, 2027.

**Topic 2: Bidirectional provider-to-payer interoperability**
- **Provision ID:** GENERAL; FHIR-IG-REQUIRED
- **Position:** Modify
- **Rationale:** BCBSMA contends that federal interoperability requirements impose API obligations mainly on payers while not requiring providers or EHRs to share data with payers for operations, claims adjudication, quality measurement, onboarding, or care management.
- **Specific request:** Require certified EHR systems to support stable, efficient bulk FHIR exports and develop a TEFCA exchange purpose for health care operations and payments with response timeframes and participation requirements.

**Topic 3: Public reporting of drug prior authorization metrics**
- **Provision ID:** TRANSPARENCY; PA-DRUG-MEDICAL
- **Position:** Modify
- **Rationale:** BCBSMA argues that Part B drug prior authorization metrics may not be comparable to non-drug prior authorization metrics and could confuse patients because medical benefit drugs differ from ordinary retail prescription drugs.
- **Specific request:** Create a one-year introductory period where MA organizations submit drug PA metrics to CMS for internal review and validation before public reporting begins.

**Topic 4: API usage metrics and further API investment**
- **Provision ID:** API-USAGE-METRICS
- **Position:** Modify
- **Rationale:** BCBSMA supports CMS evaluating actual API use but says prior mandated payer investments have not always produced robust information sharing. It argues new API requirements should wait until CMS evaluates whether usage justifies additional spending.
- **Specific request:** Pause new API implementation requirements until CMS receives and interprets API usage data and until APIs support bidirectional data flows useful to payer operations.

## 5. SOLICITATION RESPONSES

- **S12:** BCBSMA indirectly responds by noting that further technical guidance is needed before implementation of medical benefit drug prior authorization through the API.
- **S21:** BCBSMA says the timeline should be modified to the later of 12 months after final technical guidance or October 1, 2027.
- **S29:** BCBSMA supports CMS collecting API usage metrics to understand actual use of required APIs.
- **S34:** BCBSMA does not specify reporting frequency, but urges CMS to review usage data before imposing further API obligations.
- **S35:** BCBSMA focuses on CMS evaluation rather than public publication and suggests data should guide whether further investments are warranted.
- **S37:** BCBSMA raises broader implementation concerns about one-directional interoperability obligations and insufficient provider/EHR participation.

## 6. RECOMMENDATIONS

1. Finalize medical benefit drug Prior Authorization API requirements only with a compliance date tied to final technical guidance.
2. Require certified EHRs to support stable, efficient bulk FHIR exports for provider-to-payer exchange.
3. Develop a TEFCA health care operations and payment exchange purpose with response timeframes and required participation.
4. Use a one-year CMS-only validation period before public reporting of Medicare Advantage drug PA metrics.
5. Pause new API implementation requirements until CMS evaluates API usage metrics and determines that further payer investment is warranted.

## 7. CONCERNS & OBJECTIONS

- **Primary concerns:** Compliance timing; one-directional payer burden; lack of bidirectional provider data exchange; premature public reporting; insufficient evidence of API usage value.
- **Potential negative impacts cited:** Confusing public comparisons, increased payer costs, inefficient allocation of scarce resources, and continued provider-payer administrative friction.
- **Implementation barriers mentioned:** Need for technical guidance, lack of certified EHR bulk FHIR capabilities, lack of required provider participation, and uncertain comparability of Part B drug PA metrics.

## 8. SUPPORTING EVIDENCE

- **Data or statistics cited:** BCBS plans collectively provide benefits to nearly 108 million Americans.
- **Studies or research referenced:** Blue Cross Blue Shield Association prior authorization commitments; House Ways and Means Committee materials on health insurance CEOs, PBMs, and hospital system CEOs.
- **Examples provided:** Provider onboarding, claims adjudication, quality measurement, and care management as use cases requiring provider-to-payer data flow.

## 9. IMPACT ASSESSMENT

- **Affected stakeholders:** MA organizations, payers, providers, EHR vendors, CMS, patients, and members.
- **Economic implications:** BCBSMA emphasizes scarce resources and argues that API investments should be justified by actual use and benefit.
- **Technical feasibility:** Feasibility depends on final CMS technical guidance and EHR support for bulk FHIR exports.
- **Patient care impact:** The commenter expects streamlined PA to help members and providers, but warns that confusing public metrics could mislead patients.
