- **Author/Organization name:** Consumers' Checkbook/Center for the Study of Services; signed by Eric Ellsworth, Director, Health Policy and Innovation.

- **Credentials or expertise mentioned:** Health policy and innovation role; experience analyzing Transparency in Coverage (TIC) files, provider directories, and consumer shopping use cases.

## 2. EXECUTIVE SUMMARY

This attachment comments on a separate Transparency in Coverage proposed rule, but its concerns overlap with interoperability and transparency issues relevant to CMS-0062-P. The commenter supports network-level TIC files but urges CMS to move beyond ambiguous network names by adopting standardized network identifiers through an open, multi-stakeholder working group.

## 3. REGULATORY CONTEXT

- **Specific provisions addressed:** GENERAL; API-ENDPOINT-REPORTING and FHIR-IG-REQUIRED indirectly through references to FHIR Provider Directory APIs and standardized technical artifacts.
- **Regulatory citations mentioned:** No CFR sections; references CMS-9882-P and CMS-0057.
- **Standards referenced:** FHIR Provider Directory APIs; TIC file schemas; standardized network identifiers; NHTSA VIN decoder analogy.

## 4. DETAILED POSITIONS

**Topic 1: Network-Level Transparency in Coverage Data**
- **Provision ID:** GENERAL
- **Position:** Support
- **Rationale:** Network-level files better align data elements with contracts and price schedules, making files smaller and improving data quality.
- **Specific request:** Preserve and improve the network-level data file approach.

**Topic 2: Standardized Network Identifiers Instead of Network Names**
- **Provision ID:** GENERAL
- **Position:** Modify
- **Rationale:** Network names are ambiguous, inconsistently used by carriers, and insufficient for linking plan designs, provider directories, rates, PA requirements, and medical necessity criteria.
- **Specific request:** Adopt a formal standardized network identifier with oversight over correct insurer use.

**Topic 3: Provider Directory and Interoperable API Linkage**
- **Provision ID:** FHIR-IG-REQUIRED; GENERAL
- **Position:** Clarify
- **Rationale:** Apps using FHIR Provider Directory APIs required under CMS-0057 need a clear network identity to query the correct network.
- **Specific request:** Ensure standardized identifiers can be used across TIC files, provider directories, and consumer shopping applications.

**Topic 4: Working Group and Sub-Regulatory Maintenance**
- **Provision ID:** GENERAL
- **Position:** Modify
- **Rationale:** A transparent industry working group can develop a robust identifier structure and assignment process, with schemas updated through existing sub-regulatory processes.
- **Specific request:** Convene a working group including providers, insurers, and consumer advocates; use GitHub/reference schemas to validate implementation.

## 5. SOLICITATION RESPONSES

No CMS-0062-P numbered solicitation is directly answered. The comment is relevant to general RFI solicitations (S66-S82) on interoperability and transparency, and indirectly to S1-S3 because it discusses standards adoption, versioning, and sub-regulatory maintenance outside full rulemaking.

## 6. RECOMMENDATIONS

1. Adopt a standardized network identifier rather than relying on network names.
2. Establish oversight to ensure correct use of network identifiers by insurers.
3. Convene an open working group with providers, insurers, and consumer advocacy groups.
4. Build identifiers that support customized employer-plan network variants.
5. Validate conformance using existing sub-regulatory update processes and reference schemas.
6. Enable consumers and apps to link plans, rates, provider directories, and coverage rules accurately.

## 7. CONCERNS & OBJECTIONS

- **Primary concerns:** Ambiguous network names, inability to link data to plan designs and provider directories, and consumer confusion.
- **Potential negative impacts cited:** Degraded TIC data quality; inaccurate consumer shopping; difficulty identifying rates, networks, PA requirements, and medical necessity criteria for a specific plan.
- **Implementation barriers mentioned:** Need for robust identifier structure, assignment processes, insurer oversight, and multi-stakeholder agreement.

## 8. SUPPORTING EVIDENCE

- **Data or statistics cited:** None.
- **Studies or research referenced:** Prior work by the commenter on standardized identifiers; attached FAQ and working-group proposal.
- **Examples provided:** Different names for the same network, same/similar names for different networks, provider-directory filters by plan or network, and VIN-style identifier decoding.

## 9. IMPACT ASSESSMENT

- **Affected stakeholders:** Consumers, employers, insurers, providers, app developers, and data users of TIC and provider directory information.
- **Economic implications:** Standard identifiers could reduce burden and confusion in producing and using TIC files and improve market efficiency.
- **Technical feasibility:** Feasible if developed through a working group and maintained through schemas/reference artifacts.
- **Patient care impact:** Indirect but meaningful for consumers choosing in-network care and understanding coverage requirements.
