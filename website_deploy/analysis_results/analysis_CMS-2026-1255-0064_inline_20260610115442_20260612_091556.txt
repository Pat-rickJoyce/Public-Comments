## 2. EXECUTIVE SUMMARY

The commenter supports CMS's modernization of prior authorization and expansion of electronic prior authorization to medications. The comment recommends that CMS focus on EHR workflow integration, real-time decisioning, actionable structured denial information, provider usability, AI-enabled documentation reuse, and performance measures that capture patient access and clinician burden rather than API usage alone.

## 3. REGULATORY CONTEXT

- **Specific provisions addressed:** PA-DRUG-MEDICAL; PA-DRUG-PHARMACY; FHIR-IG-REQUIRED; PA-DENIAL-REASONS; API-USAGE-METRICS; GENERAL.

- **Standards referenced:** FHIR-based APIs; in-context clinical decision support; Real-Time Prescription Benefit tools; EHR workflows; structured reason codes; AI-assisted clinical tools.

## 4. DETAILED POSITIONS

**Topic 1: Workflow integration over digitization**
- **Provision ID:** FHIR-IG-REQUIRED
- **Position:** Modify
- **Rationale:** Portal-based or fragmented electronic tools may digitize PA without reducing provider burden.
- **Specific request:** Prioritize true EHR-integrated ePA workflows using FHIR-based, in-context clinical decision support.

**Topic 2: Real-time or near-real-time decisions**
- **Provision ID:** PA-DRUG-MEDICAL; PA-DRUG-PHARMACY
- **Position:** Modify
- **Rationale:** FHIR APIs and RTPB tools create an opportunity to approve requests immediately when criteria are met.
- **Specific request:** Incentivize immediate approvals and point-of-care decisioning to minimize therapy delays.

**Topic 3: Actionable denial transparency**
- **Provision ID:** PA-DENIAL-REASONS
- **Position:** Modify
- **Rationale:** Reason codes alone may not help providers resolve denials unless they identify next steps.
- **Specific request:** Require structured, clinically relevant next steps such as covered alternatives, documentation gaps, or criteria thresholds usable inside EHR workflows.

**Topic 4: Avoid burden shifting to providers**
- **Provision ID:** GENERAL
- **Position:** Clarify/Modify
- **Rationale:** Multiple electronic tools without usability and integration expectations can move administrative burden from payers to provider teams.
- **Specific request:** Include usability expectations and provider workflow impact in compliance and reporting.

**Topic 5: AI-enabled documentation and automation**
- **Provision ID:** GENERAL
- **Position:** Support/Modify
- **Rationale:** Ambient documentation and AI-assisted tools can generate structured data useful for PA, but manual re-entry would undercut efficiency.
- **Specific request:** Ensure structured data from AI-assisted clinical tools can populate and submit PA requests without extra manual effort.

**Topic 6: Performance measurement**
- **Provision ID:** API-USAGE-METRICS
- **Position:** Modify
- **Rationale:** API usage alone does not directly measure patient access or clinician burden.
- **Specific request:** Track time from order to authorization decision, time to therapy initiation, and provider time spent per authorization.
