    # Comment Analysis Template: CMS-2026-1255-0001

## 1. COMMENTER INFORMATION

- **Author/Organization name:** Amazon.com, Inc.
- **Stakeholder type:** Technology Vendor / Pharmacy / Cloud services organization.
- **Credentials or expertise mentioned:** Operates Amazon Pharmacy, One Medical, AWS HealthLake, and Amazon Connect Health; describes AI, FHIR, and cloud infrastructure capabilities.

## 2. EXECUTIVE SUMMARY

Amazon broadly supports standards-based APIs and electronic prior authorization, especially CMS alignment of medical benefit drug PA with the FHIR approach from the 2024 final rule. Amazon recommends moving toward a single FHIR-based ePA framework for both medical and pharmacy benefit drugs, rather than maintaining dual FHIR and NCPDP tracks.

## 3. REGULATORY CONTEXT

- **Specific provisions addressed:** PA-DRUG-MEDICAL; PA-DRUG-PHARMACY; FHIR-IG-REQUIRED; PA-TIMEFRAMES-DRUGS; API-ENDPOINT-REPORTING; HIPAA-PA-STANDARDS indirectly.
- **Regulatory citations mentioned:** No CFR sections; references CMS-0062-P and the 2024 CMS Interoperability and Prior Authorization final rule.
- **Standards referenced:** FHIR; Da Vinci specifications; NCPDP standards; APIs; AWS HealthLake FHIR capabilities.

## 4. DETAILED POSITIONS

**Topic 1: FHIR-based ePA for medical benefit drugs**
- **Provision ID:** PA-DRUG-MEDICAL / FHIR-IG-REQUIRED
- **Position:** Support
- **Rationale:** Aligning medical benefit drug PA with the FHIR-based approach for services will streamline implementation and data exchange between providers and payers.
- **Specific request:** Finalize FHIR-based medical benefit drug ePA requirements.

**Topic 2: Dual standards for pharmacy benefit drugs**
- **Provision ID:** PA-DRUG-PHARMACY
- **Position:** Modify
- **Rationale:** Dual-track FHIR/NCPDP standards add complexity, backend translation costs, and continued friction between systems.
- **Specific request:** Create an option to use FHIR for pharmacy benefit drug ePA, consider enforcement discretion for all-FHIR workflows, and potentially adopt NCPDP only temporarily before transitioning to FHIR-only.

**Topic 3: Decision timeframes and AI-enabled workflow acceleration**
- **Provision ID:** PA-TIMEFRAMES-DRUGS
- **Position:** Support
- **Rationale:** Electronic exchange and agentic AI can help providers and payers identify information requests and streamline reviews.
- **Specific request:** Finalize reduced response times, including QHP 72-hour response requirements.

**Topic 4: API endpoint reporting**
- **Provision ID:** API-ENDPOINT-REPORTING
- **Position:** Support
- **Rationale:** Endpoint reporting can enable centralized payer endpoint directories needed for scalable ePA API adoption.
- **Specific request:** Finalize payer API endpoint availability reporting.

## 5. SOLICITATION RESPONSES

- **S1/S2/S18:** Supports required FHIR-based standards and Da Vinci specifications for PA workflows, at least for medical benefit drugs.
- **S12:** Supports medical benefit drug FHIR ePA and states AWS services can support implementation.
- **S14/S22/S25:** Raises concerns about maintaining NCPDP for pharmacy benefit ePA and recommends FHIR options or transition to FHIR-only.
- **S21:** Supports reduced response times and argues electronic exchange plus AI can expedite access.
- **S23/S24/S33:** Supports API endpoint reporting and centralized endpoint directory development.
- **S44/S46/S53:** Indirectly supports broader FHIR-based standardization and phased transition away from dual/legacy approaches.

## 6. RECOMMENDATIONS

1. Finalize FHIR-based ePA for medical benefit drugs.
2. Establish a clear, consistent, end-to-end FHIR-based framework for all PA workflows across medical and prescription benefits.
3. Assess an option for providers to use FHIR for pharmacy benefit drug ePA.
4. Offer enforcement discretion for organizations that use FHIR for all ePA transactions.
5. If retaining NCPDP initially, make it time-limited and transition to FHIR-only within a few years.
6. Finalize payer API endpoint reporting to support centralized directories.

## 7. CONCERNS & OBJECTIONS

- **Primary concerns:** Complexity from dual-track standards; backend translation between NCPDP and FHIR; continued friction and proprietary integration burden.
- **Potential negative impacts cited:** Added costs, burden, and failure to achieve unified data exchange.
- **Implementation barriers mentioned:** Mapping between benefit categories and standards; pharmacy benefit standards fragmentation; need for standards community collaboration.

## 8. SUPPORTING EVIDENCE

- **Data or statistics cited:** Amazon Pharmacy uses AI to get prescriptions into patients' hands 90% faster.
- **Studies or research referenced:** None.
- **Examples provided:** Amazon Pharmacy AI, One Medical generative AI administrative tools, Amazon Connect Health agentic AI, AWS HealthLake FHIR support.

## 9. IMPACT ASSESSMENT

- **Affected stakeholders:** Patients, providers, pharmacies, payers, technology vendors, standards developers.
- **Economic implications:** Single FHIR approach could reduce integration and translation costs; dual standards may increase costs.
- **Technical feasibility:** Amazon asserts FHIR-based infrastructure is already supportable through AWS capabilities; acknowledges pharmacy-benefit FHIR IG work is emerging.
- **Patient care impact:** Faster ePA and real-time adjudication could reduce pharmacy counter abandonment and medication access barriers.
