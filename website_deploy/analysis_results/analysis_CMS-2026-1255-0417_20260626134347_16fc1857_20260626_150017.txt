## 1. COMMENTER INFORMATION

- **Author/Organization name:** Texas Health and Human Services Commission (HHSC)
- **Stakeholder type:** Government (State Medicaid/CHIP agency)
- **Credentials or expertise mentioned:** Administers one of the nation's largest Medicaid managed care programs serving 4 million+ beneficiaries through contracted MCOs; operates the Emergency Department Encounter Notification (EDEN) System; operates the Texas HHS Cybersecurity Operations Center (CSOC)

---

## 2. EXECUTIVE SUMMARY

Texas HHSC raises broad concerns about administrative burden, system complexity, timeline conflicts, and cost for the proposed rule's October 1, 2027 compliance date. The comment provides detailed technical analysis across six key provisions and four RFIs, with particular emphasis on conflicts between the new NCPDP standards implementation timeline (early 2028) and the proposed rule's requirements, security expectations for API endpoints, FHIR adoption challenges for legacy systems, and the need for standardized, machine-readable step therapy rules. HHSC requests federal funding support and a minimum four-year implementation window.

## 4. DETAILED POSITIONS

**Topic 1: NCPDP Standards Timeline Conflict**
- **Provision ID:** PA-DRUG-PHARMACY
- **Position:** Oppose (timeline concern)
- **Rationale:** States are currently transitioning to NCPDP Telecommunication Version F6, SCRIPT v2023011, F&B Version 60, and RTPB Version 13 by early 2028. Requiring simultaneous implementation of new NCPDP standards and new PA requirements by October 1, 2027 creates compounding coordination challenges across thousands of stakeholders.
- **Specific request:** Develop a process to allow states to obtain federal funding; allow a minimum of four years to implement (i.e., no earlier than ~2030).

**Topic 2: FHIR for HIPAA PA Transactions**
- **Provision ID:** HIPAA-PA-STANDARDS
- **Position:** Modify
- **Rationale:** FHIR facilitates integration but does not address consistent interpretation of rules and criteria across payers. Many existing systems are built on legacy standards requiring significant transformation. FHIR-based PA needs full lifecycle tracking—clear statuses, timestamps, and reason codes—not addressed by FHIR alone.
- **Specific request:** Support phased implementation expectations, defined testing and conformance support, and guidance for operating legacy and FHIR-based processes in parallel during transition to reduce operational risk.

**Topic 3: API Endpoint Reporting and Security**
- **Provision ID:** API-ENDPOINT-REPORTING
- **Position:** Modify
- **Rationale:** Secure APIs must enforce strong authentication, encrypted communication, input validation, and monitoring per NIST, OWASP API Security Top 10, and applicable state/federal security requirements. Some providers lack infrastructure or funding for API development.
- **Specific request:** CMS must clearly recognize security expectations (NIST, OWASP) as part of implementation. Provide a time-limited exception or phased compliance pathway for providers lacking API capabilities, with defined criteria, minimum security safeguards, and progress requirements during transition.

**Topic 4: Additional Standards / ONC Standards Update**
- **Provision ID:** ONC-STANDARDS-UPDATE, FHIR-IG-REQUIRED
- **Position:** Modify
- **Rationale:** If additional or clarified requirements are introduced in the final rule, insufficient time exists to implement, test, and validate across MCO vendors. Standards version drift can break interoperability between plans and providers. Ongoing upgrade, regression testing, and recertification burdens increase oversight complexity.
- **Specific request:** CMS must account for operational and governance impacts; support coordinated implementation with timely adoption and proof of testing; require consistent conformance targets and coordinated cutover windows.

**Topic 5: Prior Authorization Timeframes**
- **Provision ID:** PA-TIMEFRAMES-DRUGS
- **Position:** Modify (technical concerns)
- **Rationale:** 24-hour drug PA deadlines require greater automation and straight-through processing because manual workflows will not scale. Robust state management (clear statuses, timestamps, correlations) needed to avoid missed clocks. Near-real-time integrations with provider systems needed to eliminate hidden batch delays.
- **Specific request:** Define implementation expectations balancing security, logging, and audit with system performance; establish minimum API performance expectations (response time, throughput); encourage scalable, non-blocking architectures.

**Topic 6: API Usage Metrics Reporting**
- **Provision ID:** API-USAGE-METRICS
- **Position:** Modify (clarification needed)
- **Rationale:** Expanded metrics require centralized API telemetry across Patient Access, Provider Access, Payer-to-Payer, and PA APIs. Normalizing metric definitions across vendors and ensuring metrics reflect real usage (not idle endpoints) are ongoing challenges.
- **Specific request:** Define standardized API usage metric definitions, reporting formats, and submission requirements; specify required metrics, reporting frequency, and aggregation approaches; clarify how usage should be measured (treatment of automated traffic, retries, low-volume endpoints).

**Topic 7: Electronic Event Notifications RFI**
- **Provision ID:** GENERAL
- **Position:** Support with detailed recommendations
- **Rationale:** Texas operates the EDEN system for 4 million+ Medicaid beneficiaries through MCOs; MCOs are the primary vehicle for care coordination, making ADT notifications a critical operational necessity, not optional. Current MCO notification is permissive under QSO-21-18, not required.
- **Specific request:** (1) Standardize supplemental ADT data elements (ICD-10 codes, disposition, physician NPI, MCO/payer identifier, behavioral health flags with Part 2 compliance, SDOH flags). (2) Establish FHIR as alternative compliance pathway near-term, required standard medium-term. (3) Amend 42 CFR 482.24(d) to require MCO notification for enrolled members. (4) Leverage TEFCA for standardized cross-network ADT routing. (5) Develop outcome-oriented compliance metrics (delivery rate, recipient acknowledgment rate). (6) Add ADT notification delivery metrics to Medicare Promoting Interoperability Program; develop parallel Medicaid-specific incentive for hospitals not subject to Medicare PI.

**Topic 8: Health Care Resiliency RFI**
- **Provision ID:** GENERAL
- **Position:** Support / Offer to partner
- **Rationale:** Texas HHSC Cybersecurity Operations Center (CSOC) coordinates cyber threat response with state and federal partners.
- **Specific request:** Texas HHSC's CSOC is willing to partner with CMS on health care resiliency defenses.

**Topic 9: API Security RFI**
- **Provision ID:** GENERAL
- **Position:** Support with specific standards
- **Rationale:** Texas HHS requires penetration testing prior to production release of systems containing PII/PHI and ongoing security testing. Standardized, repeatable testing expectations would reduce security findings that delay production release.
- **Specific request:** Establish standardized security testing expectations: pre-production testing aligned with NIST 800-53 and OWASP API Security Top 10; independent penetration testing; continuous vulnerability scanning; certification/attestation requirements before deployment.

**Topic 10: Step Therapy RFI**
- **Provision ID:** GENERAL
- **Position:** Support reform with technology-focused approach
- **Rationale:** Root cause of step therapy failures is lack of standardized, shareable rules and inconsistent access to historical patient data across payers. Differences in how payers define step completion and apply criteria result in inconsistent determinations.
- **Specific request:** Standardize step therapy rules using machine-readable structured criteria; enable secure data exchange via Payer-to-Payer APIs so prior steps follow the patient; require payers to honor prior step therapy decisions; require clear explanations of criteria applied; encourage rules-based decision-making with automated structured data extraction while maintaining auditability.

## 6. RECOMMENDATIONS

1. Develop a process for states to obtain federal funding to support system change costs.
2. Allow a minimum of four years to implement (not October 2027).
3. Support phased FHIR implementation with parallel legacy/FHIR operation during transition; provide testing and conformance support.
4. Recognize NIST and OWASP security standards as required for API endpoint submissions.
5. Create time-limited exception or phased compliance pathway for providers lacking API infrastructure.
6. Establish minimum API performance expectations (response time, throughput) and encourage scalable, non-blocking architectures.
7. Define standardized API usage metric definitions, reporting formats, and aggregation approaches.
8. Standardize supplemental ADT data elements for electronic event notifications.
9. Amend 42 CFR 482.24(d) to require mandatory MCO notification for enrolled members.
10. Leverage TEFCA for standardized cross-network ADT routing.
11. Add ADT notification metrics to Medicare Promoting Interoperability Program; develop parallel Medicaid-specific incentive.
12. Establish standardized API security testing requirements (NIST 800-53, OWASP, independent penetration testing, continuous scanning, certification before deployment).
13. Standardize step therapy rules using machine-readable criteria; enable Payer-to-Payer step therapy history sharing; require honoring of prior step therapy decisions.

## 7. CONCERNS & OBJECTIONS

- **Primary concerns:** October 2027 timeline conflicts with ongoing NCPDP standards transition (early 2028); simultaneous implementation of multiple major standard sets across thousands of stakeholders; security risks from inadequately secured API endpoints; legacy system transformation within 24 months for FHIR HIPAA PA standard.
- **Potential negative impacts cited:** Communication, system testing, and integration failures from concurrent implementation; standards version drift breaking interoperability; security vulnerabilities in PA APIs handling PHI; providers lacking infrastructure unable to meet deadlines.
- **Implementation barriers mentioned:** Coordination with thousands of stakeholders; MCO vendor contract and compliance update timelines; state data use agreement governance amendments; EHR vendor variability in ADT data elements; limited health IT capacity of small/rural hospitals; absence of standardized API testing frameworks.

ORIGINAL COMMENT EXCERPT
------------------------
The Texas Health and Human Services Commission (HHSC) appreciates the opportunity to comment on the Centers for Medicare & Medicaid Services (CMS) proposed rule: Medicare and Medicaid Programs; Patient Protection and Affordable Care Act; Interoperability Standards and Prior Authorization for Drugs for Medicare Advantage Organizations, Medicaid Managed Care Plans, State Medicaid Agencies, Children's Health Insurance Program (CHIP) Agencies and CHIP Managed Care Entities, and Issuers of Qualified Health Plans on the Federally-Facilitated Exchanges[CMS–0062–P].

General Comment:
Texas HHSC has concerns regarding the administrative burden, the amount of system changes required, the timeline for compliance, and the cost associated with implementing the proposed rule. A specific area of concern is the use of NCPDP to process all drug prior authorizations. The proposed rule requires implementation by October 1, 2027. However, states are currently working on transitioning to the new required NCPDP Telecommunication Standard Version F6, SCRIPT Standard v2023011, NCPDP Formulary & Benefit Standard Version 60, and NCPDP Real Time Prescription Benefit Standard Version 13 by early 2028. Implementing the new NCPDP standards and the requirements of this rule at the same time is problematic because it involves coordination with thousands of different stakeholders who must update systems, processes, and implement at the same time with the proposed APIs and workflow, presenting communication, system testing, and integration challenges. HHSC recommends CMS develops a process to allow states to obtain federal funding to support the cost of the system changes and allow a minimum of four years to implement...
